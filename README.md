# Age of War (vanilla HTML/CSS/JS)

Web recreation of the Flash game *Age of War* (original by louissi). No framework, no runtime dependencies.

## Run
```
python3 serve.py 8000            # static server with caching disabled; ES modules need http://, not file://
# open http://localhost:8000
python3 serve.py 9000            # different port
python3 serve.py --host 0.0.0.0  # also reachable from other devices, e.g. open http://<your-LAN-ip>:8000 on a phone
```
`serve.py` binds to `127.0.0.1` by default. `--host 0.0.0.0` exposes the whole project directory (including
`references/`) to your network, so use it only on a trusted network.
Tests (simulation rules): `node --test test/`

If you ever see wrongly cropped sprites or missing HUD icons after regenerating assets, it is a stale browser cache
mixing old and new files: hard-reload (Ctrl+Shift+R). Images are content-hashed and `meta.json` is revalidated, but
plain `python3 -m http.server` sends no cache headers for the JS files.

## Deploy on Render (Static Site)
The game is plain static files, so it needs no server code. Only `index.html`, `game.html`, `css/`, `js/` and `assets/` are needed
at runtime. Do not publish `references/` (about 9,700 decompiled files) or `tools/`.

1. Commit the generated `assets/` folder (it is built from `references/` by `tools/pack.py`, which Render does not run),
   then push the repo to GitHub/GitLab.
2. In the Render Dashboard choose **New > Static Site**, connect the repo and pick the branch.
3. Set the build details:
   - **Build Command**: `mkdir -p dist && cp -r index.html game.html css js assets dist/`
   - **Publish Directory**: `dist`
4. Click **Create Static Site**. Render deploys on every push to that branch.

Equivalent `render.yaml` (Blueprint):
```yaml
services:
  - type: web
    name: age-of-war
    runtime: static
    buildCommand: mkdir -p dist && cp -r index.html game.html css js assets dist/
    staticPublishPath: ./dist
```

Optional, recommended: make sure browsers never mix old and new files after a redeploy (the stale-cache problem above).
In the site's **Headers** settings add (path wildcards as in Render's header docs):

| Path | Name | Value |
|---|---|---|
| `/*` | `Cache-Control` | `no-cache` |
| `/assets/*.webp` | `Cache-Control` | `public, max-age=31536000, immutable` |

The `.webp` file names contain a content hash, so they can be cached forever; HTML, JS, CSS and `assets/meta.json` are
revalidated on each load. [Unverified] I could not confirm Render's default `Cache-Control` values, whether a later,
more specific header overrides `/*`, or the `headers:` field names inside `render.yaml`; check Render's
"Static site headers" page and test with `curl -I <your-url>/assets/meta.json`.

The music file (`assets/snd/1035.mp3`, 2.2 MB) is the largest asset; total site size is about 5 MB.

## Controls
Mouse: click the HUD buttons, move to the screen edges to scroll. Touch: tap, drag the battlefield to scroll.
Keys: Space pause, Esc cancel, arrows/A/D scroll, 1-6 menu buttons. Portrait phones show a "rotate your device" screen.

## Layout
- `js/data.js` tables from the decompiled Flash code · `js/sim.js` DOM-free simulation (40 Hz) · `js/render.js` canvas + atlas loading
- `js/ui.js` HUD · `js/audio.js` sound · `js/main.js` loop, layout, input
- `assets/` generated by `tools/pack.py` (needs Pillow and `references/age_of_war_decompiled`); `assets/meta.json` holds atlas rects and anim data

## Memory
Unit art is packed into one trimmed, de-duplicated, frame-decimated atlas per age and loaded on demand; atlases of ages with no living units are closed (`ImageBitmap.close()`). Sim objects are pooled.

## Known approximations
- Age names, sound-to-event mapping, turret pivots and unit sprite anchors are my estimates (the decompiled data has none).
- Wide screens show more of the 1000 px world than the original 650 px view.
